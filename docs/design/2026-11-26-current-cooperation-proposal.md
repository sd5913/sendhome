# 《送小鱼回家》差异化设计方案 v1：水流中的合作

日期：2026 年 11 月 26 日（香港时间）  
状态：**已确定探索方向，待实现及试玩验证**。本次只提交设计方案，不宣称水流已上线。  
基线：当前三鱼、单一引擎、地编数据、实体碰撞、推挤、承载、负重跳跃及音效。

## 1. 核心定位

面向喜欢轻量解谜的玩家，保留单机切换三位伙伴的平台操作，以“拆分与组合队伍，对抗水流并互相护送”形成核心体验。

一句话介绍：**三条鱼利用不同体重与承载组合，在水流中接力，最终全员回家。**

参考来源为 Aardman 的 [Home Sheep Home](https://www.aardman.com/film-tv-games/home-sheep-home-farmageddon-party-edition/)。本项目如实承认多角色合作平台解谜的参考关系，不声称该类型或所有机制均为独创。计划以水流、组合重量与控制水流的关卡结构建立自身特色；不直接复刻原游戏地图、角色或素材。

## 2. 角色与决策

| 角色 | 已有属性 | 新机制中的用途与代价 |
| --- | --- | --- |
| A | 1×1，重量 1，速度 2 | 穿低矮通道、触发远端机关；单独逆强流困难，需要伙伴护送 |
| B | 2×1，重量 2，速度 1.5 | 搬箱、维持机关；并非所有难题都靠最重的角色解决 |
| C | 2×2，重量 4，速度 1 | 逆流运输伙伴；体型无法进入低矮通道，负重限制移动与跳跃 |

玩家需决定：在哪里搭载、谁留下操作机关、什么时候分开，以及如何接回最后一位伙伴。重量带来抗流收益，也保留现有负重代价。

不保证只有一个标准答案；若玩家利用合理的其他组合解出谜题，应保留这种解法。需要防止的是无视全部新机制、随意跳过或冲刺越过的通关方式。

## 3. 最小可交付范围

**必须完成：**

- 水平矩形水流区域，方向明确，具有开／关状态。
- 统一的组合抗流规则，复用现有承载关系及碰撞求解。
- 压板关联水流关闭，复用现有压板重量与箱子机制。
- 水流箭头、粒子、当前状态提示；音效复用共用音频模块。
- 一个可理解的小教学场景，以及一个综合合作关。

**本轮暂不纳入：**自由游泳、浮力模拟、竖向水流、复杂流体、联网、永久角色升级和大量新技能。水流反转、撤销操作作为可选后续项，不影响核心交付。

这里的水流是平台游戏中的水平环境作用，不模拟真实水动力。

## 4. 统一规则草案

1. 水流同时影响被选中与未选中的鱼，不能靠切换角色冻结漂移。
2. 当前互相支撑的鱼形成一个承载组。水流对整组只计算一次，组内保持相对位置；不得给每位乘客重复叠加位移。
3. 组合总重量沿用引擎中的实际重量，负重移动和跳跃继续使用现有规则，不为水流关修改角色参数。
4. 环境位移必须通过同一个碰撞求解器，禁止水流把鱼挤进墙、门、箱子或另一条鱼。
5. 跳离、走离后重新识别承载组；水流中的落地、叠站和脱离按每个固定物理步更新。
6. 重鱼能逆流推进，但不自动成为固定锚点：停止移动仍可能漂移。切换角色前应把伙伴停在安全区。
7. 第一版水流不直接推动箱子。箱子继续遵循已有推箱与重力规则，用于固定压板；界面应明确呈现这是受影响的鱼类区域。

### 待原型验证的抗流模型

令 `M` 为承载组总重量，`e` 为水流覆盖程度（0–1），`S` 为区域流强参数：

```text
水流漂移速度 = 方向 × S × e / M²
本步水平位移 = （现有主动移动速度 + 水流漂移速度）× dt
```

覆盖程度取组内各鱼“与区域相交面积占自身面积”的最大值，避免只触边就立即受到完整水流，也避免乘客增加时重复计力。第一版同一位置不允许放置相互重叠的水流区，避免方向抵消与强度叠加歧义。

`M²` 及下表参数只是玩法起始假设，不是已验证平衡，也不是物理真实性主张。参数统一在引擎定义；关卡只配置环境方向、强度和位置。

以全覆盖、向左水流 `S=2400` 为例，按当前全局移动参数估算：

| 组合 | 向右主动速度 | 向左漂移速度 | 预估净速度 |
| --- | ---: | ---: | ---: |
| A 单独 | 360 | 2400 | −2040，无法逆流 |
| B 单独 | 270 | 600 | −330，无法逆流 |
| C 单独 | 180 | 150 | +30，可以缓慢逆流 |
| C 承载 A | 144 | 96 | +48，可以护送 |

单位为 px/s。A 冲刺约 720、B 冲刺约 540，在该示例的全覆盖区域仍不能独自逆流；实际边界、跳跃及冲刺穿越必须通过模拟与试玩检查。高漂移速度不得绕过连续碰撞检测。若体验过猛，优先调整模型及关卡，不接受难以操控的参数仅为强制标准解法。

该模型不改变存档格式或关卡专用物理规则，旧关卡未配置水流时体验应保持一致。

## 5. 代表关卡：“逆流接力”

### 空间构成

左侧安全准备区 → 中段逆流水道 → 右侧安全拆队区 → 一格高的远端压板通道 → 可推箱的绕行路线 → 全员集合点。

水流区应覆盖可跳跃通过的高度，或以合法地形限制绕行；具体坐标、长度、顶棚与平台间距待可达性模拟后确定。本方案不将未验证地图直接作为正式关卡。

### 候选完成过程

1. 安全区内通过箭头和简短提示观察：A 进入水流会被推回，C 可以向右推进。
2. A 跳到 C 背上，由 C 把 A 运到右侧安全区。水流出口应留出足够大的停车区，不能切换后立刻滑回。
3. A 从 C 背上下来，通过一格高通道站上压板，关闭水流。C 因高度无法代替 A，B 因通道入口宽度或路线安排不能直接替代。
4. B 在水流关闭期间推箱通过，并从另一条可达路线把箱子放到同一压板上；箱子独自达到该压板门槛后，A 可安全离开。通道与绕行路线必须确保 B 能放箱、A 能退出，不能做成单向困住角色的机关。
5. 三条鱼继续抵达集合点。入口宽度、叠站空间与现有检查点规则保持一致。

压板门槛初拟为 1，A 可触发，重量 2 的箱子可维持；允许其他重量组合触发。应由地形建立协作需要，而不是写死“只有 A 才能操作”的角色判断。

### 失败恢复

- 水流入口回推区为安全地面，首次尝试不应立即掉出地图。
- 主路线失败可回到准备区重新搭载，保留长按重置与按钮重置。
- 检查开关关闭前后是否总能接回留守角色；箱子卡住可通过明确的重置恢复。
- 当前全关重置继续可用；新增检查点复位或撤销不作为首版前置条件。

## 7. 验收与测试计划

自动验证：

- 无水流的现有关卡继续通过已有测试；物理和音效验证命令保持有效。
- 区域外不受流；边界覆盖程度变化连续；暂停冻结水流位移。
- 相同覆盖下 A、B、C 的抗流差异符合统一模型。
- 两层、三层承载只受一次组合漂移，乘客不穿模、不重复计重。
- 跳离后独立漂移；未选中的鱼也受流；切换不消除已有环境作用。
- 强流碰墙、门、箱子与鱼时没有穿透；检查大位移与低帧率。
- 压板可关流，移走重量恢复；箱子能维持压板并解放 A。
- 重置恢复区域初始状态；缺少压板引用及重叠水流区被拒绝。
- 完整模拟三鱼可通关，同时检查冲刺、跳跃、推挤及其他组合的替代解法。

真人试玩：邀请至少一位未参与该机制实现的人，先不口头解释。记录是否理解流向、是否想到搭载、哪个阶段迷路／卡住、是否需要提示及完成时间。取得反馈后记录“问题 → 修改 → 再测结果”，不把设想或自动测试写成已发生的真人反馈。

初步体验目标：提示后能解释为什么需要组合；失败能看懂原因；逆流阶段不要求连续精确按键。目标值需 tutor 与试玩确认，不以强制限时制造难度。
